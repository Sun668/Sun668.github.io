从零搭建 Agent Harness 系列（十八）事件背压：有界队列、尊重 Context 与可关闭的 EventSink

发表于 2026-08-13 分类于 Agent Waline：
为 go-tiny-claw 的 JSONEventSink 增加有界事件队列，让慢客户端把压力传回 Engine，并在取消和 Session 关闭时正确退出 writer goroutine。

系列十七修好了终端审批泄漏。阶段七还剩另一件容易在生产里爆内存的事：事件比网络快时，往哪里堆？

工具并发上限限制的是「同时跑几个工具」。事件背压限制的是「事件管道别无限灌」。两者管的不是同一类资源。

二、背压是什么

把中间换成有界队列：

情况行为
队列有空位Publish 立刻返回
队列满、任务还在Publish 堵住，Engine 变慢
队列满、用户取消ctx.Done() 返回，不永久卡住
Session 关闭不再入队，writer goroutine 退出

「满了让上游慢下来」就是背压。没有界的 channel 或无限 goroutine，只是把压力变成内存。

六、测试要证明什么

test/channel/event_sink_test.go 覆盖三条：

  1. 队列有空位，Publish 立刻成功。
  2. 用会阻塞的 io.Writer 让 loop 卡在 Write 上，填满容量为 1 的队列，第三次 Publish 在 cancel 后返回 context.Canceled。
  3. Close 两次不 panic；之后 Publish 返回 ErrEventSinkClosed。

第二条最能说明背压：下游不消费时，上游必须能被 ctx 救出来，而不是永远卡在 queue <-。

为了测「满」，构造函数增加了容量参数；生产路径仍走默认 64。

七、还没做的

有界队列解决的是「别无限堆事件」。要把失败变成 Run 的终态，还得让 Reporter 把错误传回去。
